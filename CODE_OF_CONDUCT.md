# Code of conduct

ORDER is a security project, built in the open so anyone can use it, learn from it and improve
it. These are the expectations for everyone who takes part: in issues, pull requests,
discussions, and anywhere else the project is represented.

## Expected behaviour

- Be respectful and constructive, especially when you disagree.
- Assume good faith, and ask before you assume.
- Critique code and ideas, never people.
- Welcome newcomers. Everyone was new to security once.
- Credit others' work, and say clearly what you're unsure about.

## Not acceptable

- Harassment, insults, or discriminatory language of any kind.
- Personal attacks or sustained disruption of discussions.
- Publishing anyone's private information without their permission.
- Using this project, or its issue tracker, to plan or support attacks on systems you don't own.
- Posting real credentials, live exploit code against third parties, or other people's private data.

## Reporting security vulnerabilities

Vulnerabilities in ORDER itself are not conduct issues. Report them privately as described in
[SECURITY.md](SECURITY.md), not in a public issue.

## Enforcement

Report conduct problems privately to the maintainer through the contact options on the
maintainer's GitHub profile. Reports are handled confidentially.

The maintainer may remove comments, issues or contributions that break this code, and may block
anyone who does so repeatedly or seriously. Decisions take into account what happened, its
impact, and whether it's a pattern.
